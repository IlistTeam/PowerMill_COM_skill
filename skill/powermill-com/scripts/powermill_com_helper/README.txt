Прямой COM-помощник PowerMill 2023, версия 0.5.0

Изменения 0.5.0
- Объединены правила поставки от 02.11.2026 с актуальным помощником.
- COM 2023000/2023003/2023101; новые документированные функции чтения.
- Сортировка по уникальным XYZ без PP и отдельная проверка фактических PP.
- Новые модели принимаются по именованным receipt с закреплением ID на диске.
- Нативные ответы сохраняются до постпроверок с безопасным хешированным именем.
- Сохранены свежие XML-снимки, PID/ROT, аудит RobSim и таймеры 0.4.x.

Изменения 0.4.2
- Чистые XML-getter функции позиции TCP и направлений Z/X с прежними guards.
- robot_input.prepare_external_axis_input преобразует позу проекта через
  кинематический контракт в статическую СК TableAttachPoint для EXTERNALABS.
- Проверяет пределы, фиксированные внешние оси, TCP и допуск X до передачи.
- Диагностический JOG не заменяет проигрыш траектории с PP/временем и проверкой
  столкновений. Любая нативная ошибка/коллизия продолжает блокировать результат.

Изменения 0.4.1
Известные скалярные настройки проверяются по свежим полным XML-снимкам станка
и simulationstate в пределах одного набора постусловий. Те же условия и допуски
сохраняются; неизвестные выражения и скалярные XML-хеши читаются как прежде.
Отсутствующие поля запрашиваются отдельно без подстановок, полные снимки после
таких запросов обновляются. Повреждённый/неоднозначный XML или изменение структуры
останавливают очередь. Между фазами, командами и согласованием снимки не кешируются.
settings_snapshots=false в плане оставляет прежние запросы со всеми проверками.
Проверки сессии для фактических запросов и перед записью, коллизии, исходники,
PP/Z/X, хеши, маркеры, receipt и durable checkpoint сохранены. Версия проверена
офлайн; её живое ускорение не измерялось. Симуляции при разработке не менялись.

Изменения 0.4.0
Условные области движения встроены в потоковый аудит: FK каждой новой позы
считается один раз, ранее проверенные байты полностью перехешируются. Неизвестный
MOVETYPE при явной классификации блокируется; области не расширяют общую region.
prepare-simulation офлайн проверяет совместимость профиля и выбирает критические
окна по всей траектории. Профиль остаётся начальной подсказкой, полный запуск
требует успешных нативных тестов в рамках отдельного поручения.
CLI --timing-output NEW_FILE сохраняет подробные таймеры, в том числе неудачных
операций. state/events больше не теряют нативное время при отказе постусловий;
тайм-аут не объявляется известным временем расчёта. Новая версия проверена офлайн;
её ускорение на живом PowerMill не измерялось. Источники/симуляции не менялись.

Изменения 0.3.2
Полный список текущих ID моделей читается одним GetParameterXML через
extract(folder('model'),'ID') при каждой проверке сессии. ID не кешируются;
PID/версия/Busy/путь, HELP, частота проверок и контрольные точки прежние.
XML проверяется на структуру, пустые ID и дубликаты; ошибочный ответ блокирует
работу без автоматического возврата к другому способу. При обнаружении сессии
и каждом Root-Probe список дополнительно сверяется с полной COM-коллекцией.
Прежний COM-обход доступен
явно как PowerMillTransport(session_model_read='com') для сравнения/совместимости.

Изменения 0.3.1
Опциональные подробные таймеры Python/PowerShell, без изменения команд,
условий, порядка проверок и устойчивых записей. Profiler хранит результаты
в памяти; PowerMillTransport(profile=True) добавляет метрики работника в ответы.
Вложенные времена не складываются повторно; экспорт профиля выполняет вызывающий
код после замера. Подробнее — references/helper.md переносимого навыка.

Изменения 0.3.0
XML-постусловия выполняются пакетами без удаления условий, с проверкой
PID/проекта/Busy для каждого выражения и после пакета. Один run переиспользует
STA-процесс между блоками; целевой PID выбирается через ROT без возврата к
другому экземпляру. Очередь PID общая для установленных и исходных копий.
Новый simulation.py проверяет только новые строки RobSim, сохраняя контроль
неизменности префикса, исходных точек/осей/PP, суставов, TCP, X и рабочей области.
Живое постусловие также требует закреплённой геометрии/инструмента и включённых
проверок столкновений. audit-simulation работает офлайн, не перезаписывает входы.
Подробный контракт: references/simulation.md переносимого навыка.
Новая версия проверяется синтетическими тестами и чтением готовых файлов.
Живые траектории при разработке 0.3.0 не запускаются. Ускорение выполнения
внутри PowerMill отдельно не измерено; пересчёт требует поручения пользователя.

Нативное копирование/настройка/расчёт нового генератора ещё не испытаны.
Подробная схема: skills/powermill-com/references/surface.md в репозитории
либо references/surface.md в корне переносимого навыка.
Реализованы контроль состояния/возобновление и офлайн-планировщик сортировки.
Проверены имитационные сбои, отдельный рабочий процесс, реальный протокол
Windows PowerShell 5 с подставным приложением и архив 184 слоёв P1.

Материалы: ../support-study-20261021/README.txt. Добавлены документированные

Выполнение новых макросов и возобновление после реального сбоя в PowerMill
пока НЕ проверены. Проверка на следующей P2 отложена до её начала пользователем.

Состав
core.py       — план, привязка к проекту, блокировка очереди, контрольные точки.
transport.py  — JSON-канал с внешним таймером, отдельный скрытый процесс PS5.
simulation.py — потоковый аудит готовых/растущих RobSim с закреплённым контрактом.
worker.ps1    — точный PID через ROT / первоначальный GetActiveObject, HELP, GetParameterXML,
                DoCommandEx. Новое приложение PowerMill не создаёт.
surface.py    — профиль surface_machine, наборы/копии, план и аудит осей.
planner.py    — расчёт целевого порядка по явной политике, MOVE_END,
                наблюдение порядка и построение продолжения после прерывания.
replay_p1.py  — строго офлайн-проверка архивного задания P1.
validation/   — неисполняемый архивный план и результаты проверки.
tests/        — unittest без подключения к PowerMill.

Контроль состояния
1. План задаёт process_id, version=2023000, полный набор model_ids,
   при необходимости project_path. Пустая строка пути означает несохранённый
   проект и требует совпадения PID/моделей; неизвестный проект не принимается.
2. Перед командами проверяются привязка, Busy и корневой контекст HELP.
   NEW/QUIT и закрытие неизвестных диалогов автоматически не выполняются.
   Root HELP не является универсальным детектором всех открытых форм.
3. Прямые команды выполняются одним работником. Общий файловый замок по PID
   не допускает второй исполнитель этого помощника одновременно. Другие
   программы и ручные команды PowerMill этот замок не обязаны соблюдать.
4. До отправки команды записывается устойчивый checkpoint running; после
   Code=0 проверяются также текст ошибки, маркер макроса и фактические условия.
5. Внешний таймер охватывает запись запроса и ожидание ответа. По истечении
   останавливается только созданный процесс-посредник, не PowerMill.
   Команда могла выполниться частично или полностью: статус uncertain.
6. При возобновлении сначала читается результат. Совпадение postchecks
   позволяет засчитать завершение без повтора. Если результат не совпадает,
   старые относительные индексы не запускаются снова, даже при совпадении
   исходного состояния. Явный отказ работника ДО отправки команды оставляет
   pending и допускает обычную повторную проверку готовности.
7. Перепроверяется последняя завершённая точка каждого checkpoint_key.
   Для сортировки ключом служит ID траектории. Для обычных операций без
   ключа последние postchecks должны описывать накопленный стабильный результат.
8. plan.json/state.json фиксируют хеш плана и целостность checkpoint.
   Изменение плана требует нового run_dir. Это защита от случайных изменений,
   а не криптографическая защита от намеренного редактирования всех файлов.
9. events.jsonl содержит готовность, отправку, время проверок и нативного
   выполнения, остановки и согласование после прерывания. status читает его
   состояние локально, без COM.

Планировщик
На входе: layers с name, entity_id, initial, target и catalog.
UID прохода — внешний устойчивый идентификатор, не его текущий номер.
catalog содержит uid, position первого рабочего узла, layer, lp;
по возможности axis и head_pp. Неоднозначные головы/LP/слой отклоняются:
для них сначала нужна более сильная идентификация, а не догадка.
target_order(records, policy) умеет строить цель по явно указанным ключам
для замкнутых/открытых проходов. LP/CNT, углы и правила P1 к P2 автоматически
не переносятся. Пары/интервалы/порядок ролей должны быть заданы политикой задачи.

Все MOVE_END сначала симулируются. Макросы CP1251 имеют ограниченный размер,
проверки before/after, хеш содержимого и маркер завершения.
После FORM ACCEPT TPLIST макрос записывает уникальную receipt и закрывает
её файл. При согласовании interrupted-команды нужны и фактический порядок,
и эта receipt: одного видимого порядка недостаточно для подтверждения
завершения формы. Уже существующая receipt запрещает новый запуск того же
блока из нового run_dir. Выполненные блоки не переигрываются.
Макросу доверяется только конкретный файл с закреплённым хешем; общие
настройки доверия и безопасности PowerMill помощник не меняет.

Проверка порядка читает ВСЕ головы данного блока/траектории, слой и LP,
а при наличии в каталоге — оси и все PP первых точек. Геометрия и PP
читаются раздельными массивами. Это НЕ полный аудит всех рабочих точек,
концевых CNT, промежуточных осей, переходов или коллизий. Полный контроль
геометрии и PP выполняется отдельно по согласованному охвату; проверка
порядка его не заменяет. Проверочные выражения GetParameterXML ограничены
списком разрешённых функций чтения в Python и PowerShell: этот API способен
вызывать также функции, изменяющие проект.

Если сортировка прервана посередине, capture-sort снимает текущий порядок
только чтением. replan-sort строит НОВЫЙ план из него к прежней цели,
с прежними каталогом/ID/привязкой проекта. Старый run остаётся uncertain;
новый план сохраняет исходное наблюдение в replanned-from.json.
Перед исполнением нового плана фактическое состояние проверяется снова.

Таймеры блоков пока оценены по P1. При первом живом испытании на P2 нужно
использовать небольшую копию и измерить её время; измеренного ускорения
этой версии в PowerMill ещё нет. MOVE_START не включён: нативный запуск
нового варианта не проверялся. Сам алгоритм MOVE_END уменьшил число
операций архива P1 с 3522 до 3373, сохранив ту же целевую перестановку.

Использование из корня рабочей папки (Python 3.12; сторонние пакеты не нужны)
  python -m unittest discover -s powermill_com_helper/tests -t . -v
  python -m powermill_com_helper validate <bundle>/plan.json
  python -m powermill_com_helper status <run_dir>
  python -m powermill_com_helper session --connect --output session.json
  python -m powermill_com_helper capture-surface session.json <name> profile.json --connect --geometry
  python -m powermill_com_helper plan-surface <request.json> <new_bundle_dir>
  python -m powermill_com_helper plan-sort <input.json> <new_bundle_dir>
  python -m powermill_com_helper replan-sort <sort-inputs.json> <observed.json> <new_bundle_dir>

Последние две команды по умолчанию создают offline_only=true. Такой план
исполнителем заблокирован даже при --connect --allow-write.
Архив validation/p1-archive именно такой; его нельзя использовать как
указание повторно сортировать живую P1.

plan-surface также по умолчанию только офлайн. examples/surface-request.json
содержит исключительно синтетические данные, example_only=true принудительно
оставляет его офлайн даже с --enable-execution. Для реальной задачи требуется
свежий capture-surface и явные настройки, включая axis_contract. Пустое/неизвестное
направление оси или отсутствие полного аудита при require_full не засчитывается.
Полный аудит рабочих XYZ/осей малой траектории не является полным аудитом PP
и промежуточной геометрии переходов. Нормали CAD-поверхности не проверяются.

Только после разрешённого начала живого задания:
  plan-sort ... --enable-execution  — разрешить исполнение созданного плана.
  run <plan.json> <run_dir> --connect --allow-write
  reconcile <plan.json> <run_dir> --connect  — только чтение/согласование.
  capture-sort <sort-inputs.json> <observed.json> --connect  — только чтение.
Запускать эти команды при текущем запрете на начало P2 не нужно.
--connect и --allow-write — программные предохранители, они не заменяют
разрешение пользователя на конкретное рабочее задание.

Не редактировать макросы, план или receipt действующего задания. После
тайм-аута не удалять checkpoint ради повтора. Не перезапускать PowerMill
автоматически, особенно с несохранённым проектом.

Release 0.5.0 integrates the 2026-11-02 skill handoff without downgrading
0.4.2 simulation audits, fresh settings snapshots, PID/ROT binding or timing.
Supported COM profile versions: 2023000, 2023003, 2023101 (exact session match).
New read-only queries: number_selected, get_folders, active_folder,
component_has_point_parameter. Geometry-only sort identity requires unique XYZ
and does not verify PP. Native command responses are retained before postchecks.
Project rules are scoped to an authorized task; no live qualification was run.
