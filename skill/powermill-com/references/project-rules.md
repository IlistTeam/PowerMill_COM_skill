# Правила подготовки проекта

Источник обновления: переданный пользователем архив
`powermill-com-0.2.7-with-project-rules-2026-11-02.zip`.
Общие правила ниже перенесены из его навыка и project-rules/AGENTS.md.
Поручения, разрешения и приёмка старых разделов не действуют в новом задании.
Текущие указания пользователя и инструкции конкретного проекта имеют приоритет.

## Новая подготовка

- Для ПЛВ по шаблонам явно задавай `Tolerance=0.1` мм до `CALCULATE`, затем
  считай фактический допуск результата. Исторические рецепты с `0.001` мм не
  являются значением по умолчанию. Для других стратегий получай допуск из
  задания; одной сменой числа допуска уменьшение числа точек не доказывается.
- При порученном удалении коротких валиков измеряй полную длину прохода:
  удаляются только длины `<0.5` мм. Ровно `0.5` мм сохраняется. Это правило
  не поручает очистку уже готового открытого проекта.
- Исходные стоковые траектории сохраняй. Правки, геометрию, реальные оси,
  Старт/Стоп и порядок полностью проверяй на единственном источнике `Pn_правки`.
  Затем получай АДД и PP копированием проверенного результата. Целевые проверки
  слоёв, количества, порядка и фактических PP остаются обязательными.
- Для готового проекта без доказанного проверенного источника эта схема не
  подтверждает геометрию задним числом: выбирай охват по задаче и имеющимся данным.

## Ряды, порядок и параметры

На открытом участке проходы одного физического ряда начинаются с одной стороны
и заканчиваются с другой. В следующем ряду стороны меняются местами. Если шаг
задан по поверхности, определяй соседние ряды по геометрии поверхности. Глобальный
Z и `_LAYER` могут объединять несколько физических рядов и не задают их чётность.

По умолчанию поддержка, образующая базу, идёт первой, затем внутренние границы,
заполнение и наружные границы. Порядок определяется геометрической ролью, а не
именем или замкнутостью. Подтверждённые технологические исключения сохраняй.
Перестановка не меняет назначение LP/CNT соответствующих валиков.

Новые PP по умолчанию — только LP и CNT_Loff. Наличие FR/Speed/Wait в таблице
или примере не поручает их назначение. Имеющиеся параметры и `_LAYER` сохраняй.
CNT_Loff назначай только открытым рабочим проходам; согласованное положение
и смещение проверяй по фактическим точкам. Для замкнутых CNT по умолчанию нет.
Назначенные ранее PP не удаляй автоматически при смене этого правила.

Для общей сборки проверяй результат нативного объединения и фактические PP.
Если применяется изученный рецепт `POINTPAR N`, после очистки унаследованных
методов применяй пустой список и считывай реальные значения: рецепт не доказывает
сохранность PP. Сначала проверь совместимость такого рецепта с текущим проектом.

Готовый результат по умолчанию — отдельная общая траектория каждого раздела Pn.
Объединение разных разделов в одну общую траекторию требует отдельного поручения.

## Частные схемы архива

Секторы Старт/Стоп 90° с четвертями 22.5°, радиальное выращивание, массивы
отверстий, конкретные регистры внутренних контуров и размещение поддержки после
стенки описывали отдельные согласованные детали. Не переноси их числа, геометрию,
порядок и разрешения в другой проект автоматически. Для повторного применения
нужно явное указание текущего задания и проверка соответствующей геометрии.

Сохранённую RobSim связывай с точной редакцией проекта/траектории, включая карту
RobotInterface.PriProj и суффиксы версий. В старой записи не подтверждены текущая
кинематика, стратегия и отсутствие столкновений при новом прогоне.

## Обновление и передача

Не заменяй действующий AGENTS.md полной хронологией поручений из чужого проекта.
Не включай PID, model ID, session-now.json, геометрию, журналы и checkpoint в
публикуемый навык. Поставка собирается из исходного allowlist и проверяется
по SHA-256. Обновление кода само по себе не разрешает живое испытание.
