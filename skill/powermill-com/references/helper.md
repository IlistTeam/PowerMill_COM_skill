# Помощник и возобновление

Для диагностики систем координат разрешены документированные чистые функции
PowerMill 2023 `tool_tip_position`, `tool_axis_direction` и
`orientation_vector_direction` через `read_xml`, с необязательным аргументом
сущности СК. Они только читают положение прикреплённого инструмента. Без
аргумента используют `SimulationState.ToolPosition.WorkplaneType/WorkplaneName`;
эти поля нужно читать вместе с позой, чтобы не смешать системы координат.
Документация: установленный `lib/locale/C/PARREF/stdlib.html`, разделы этих
трёх функций. Не заменяй XML-чтение строкой `PRINT имя_функции()`:
командный разбор PRINT отличается от разбора выражений. Проверки сессии,
корневого контекста и запрет изменяющих/неизвестных функций остаются прежними.

В переносимой поставке код лежит в `scripts/powermill_com_helper` в корне
навыка. В исходном Git-репозитории канонический код — `powermill_com_helper`
в корне репозитория; сборщик кладёт актуальную копию в переносимый навык.
Нужны Windows, открытый PowerMill 2023, Python 3.12+, Windows PowerShell 5.
Сторонние Python-пакеты помощнику не нужны. Версия 0.5.0. Посредник скрытый, STA;
для плана/capture он привязывается к PID через ROT. GetActiveObject используется
только для первоначального обнаружения, когда PID ещё неизвестен.

Выполняй из `scripts` поставки либо корня репозитория:

```text
python -m powermill_com_helper session --connect --output session.json
python -m powermill_com_helper capture-surface session.json PATH_NAME profile.json --connect --geometry
python -m powermill_com_helper plan-surface surface-request.json NEW_BUNDLE
python -m powermill_com_helper plan-sort sort-input.json NEW_BUNDLE
python -m powermill_com_helper validate NEW_BUNDLE/plan.json
python -m powermill_com_helper status RUN_DIR
```

session только читает. JSON с version/process_id/model_ids/project_path подходит
как guard; проверь, что проект соответствует заданию. Импорт модулей,
plan/validate/status не подключаются к PowerMill.

При известном PID: `session --connect --process-id PID --output session.json`.
При заданном PID нет возврата к другому экземпляру PowerMill. После перезапуска
приложения заново снимай сессию; старый план/guard не переиспользуй.

Несколько блоков одного задания собирай в один план и запускай одним `run`:
STA-процесс и COM-объект сохраняются между операциями. В Python можно использовать
`with PowerMillTransport(connect=True, process_id=guard['process_id']) as transport`.
Не создавай новый процесс на каждую точку или отдельный параметр. XML-постусловия
отправляются пакетами без удаления проверок; guard проверяется перед каждым
выражением и после пакета. Таймер, белый список функций и запрет повтора при
неопределённом исходе остаются обязательными. Блокировка PID общая для копий
помощника в репозитории и установленном навыке, в пользовательской временной папке.
Перед обновлением не оставляй активный запуск старой версии помощника.

В 0.3.2 каждый guard читает полный текущий список ID моделей через один
`GetParameterXML("extract(folder('model'),'ID')")`. Это те же ID сущностей,
что у COM-моделей; имена/количество не заменяют идентичность. Кеш значений,
пропуск проверок или уменьшение частоты не используются. XML обязан содержать
массив непустых уникальных строк; неполный или ошибочный ответ останавливает
работу без автоматического fallback. PID, версия, Busy, путь проекта и HELP
по-прежнему проверяются. При обнаружении сессии и каждом Root-Probe список
независимо сверяется с полной COM-коллекцией; расхождение блокирует команду.
Для явного сравнения со старым обходом моделей:
`PowerMillTransport(..., session_model_read='com')`. Между сериями сравнений
проверяй одинаковые ID и неизменность исходников; не меняй режим внутри worker.

Подробные таймеры 0.3.1 включаются явно: `with timing.Profiler() as profile`
и `PowerMillTransport(..., profile=True)`. Оборачивай измеряемую область в
`with timing.span('trial')`. `profile.snapshot()` возвращает вложенные интервалы
Python и счётчики PowerShell: поля сессии, модели, путь, HELP и получение XML.
Проверки, их порядок, тайм-ауты и fsync остаются прежними. Измерения хранятся
в памяти, экспортируй их после замера, чтобы не добавлять дисковые записи.
`seconds` включают вложенные интервалы, `self_seconds` исключают их. Счётчики
работника находятся внутри времени transport.roundtrip; их нельзя прибавлять
к нему повторно. Учитывай влияние профилирования и остаток неизмеренного времени.

Планировщики по умолчанию создают offline_only=true. Для разрешённого живого
задания сформируй новую сборку с --enable-execution, проверь входы, затем:

```text
python -m powermill_com_helper run NEW_BUNDLE/plan.json RUN_DIR --connect --allow-write
python -m powermill_com_helper reconcile NEW_BUNDLE/plan.json RUN_DIR --connect
```

Флаги не заменяют разрешение пользователя; уже полученное разрешение
на данную задачу из-за наличия этих флагов повторно не запрашивается.
state.json пишется до команды. После обрыва операция uncertain, даже если
PowerMill мог её закончить. Завершённые блоки не переигрываются. Для признания
завершения нужны постусловия и receipt после нативного этапа. Новая копия
поверхности получает файл со своим ID: одинакового имени недостаточно.
Не удаляй checkpoint/receipt ради обхода блокировки, не редактируй действующий
план. При смене PID/проекта или повреждении состояния сначала сверяй данные.

Для частичной сортировки:

```text
python -m powermill_com_helper capture-sort SORT_INPUT observed.json --connect
python -m powermill_com_helper replan-sort SORT_INPUT observed.json NEW_BUNDLE
```

Каталог идентифицирует все головы проходов по XYZ/слой/LP; неоднозначные головы
отвергаются. Оси/другие PP голов проверяются, если включены в каталог.
Цель по слоям/ролям/парам задаётся явно; P0/P1 не определяют политику P2.
Это не полный аудит всех точек и переходов.

Ошибка Windows 1385 одного механизма не доказывает недоступность остальных:
различай запуск процесса, UI-автоматизацию и COM. Не меняй права Windows;
используй доступный прямой COM с внешним тайм-аутом.

В 0.4.1 Executor по умолчанию проверяет известные скалярные настройки по свежим
`simulationstate` и `entity('machinetool','')`. Все исходные условия, сравнения
и допуски плана сохраняются. Флаг плана `settings_snapshots: false` явно включает
прежнее чтение отдельных полей для сравнения или совместимости; он не отключает
проверки. Флаг обязан быть boolean и входит в хеш неизменяемого плана.

Снимок ограничен одним непрерывным набором XML-проверок. Полные XML читаются
после остальных выражений этого набора. Если сразу следует recording, последними
читаются станок, инструмент и simulationstate — этот же свежий набор используется
для проверки живого контракта. Он потребляется один раз. Перед следующим набором,
другим видом проверки, согласованием состояния или новой командой старые значения
не используются. Проверка живого контракта перед следующей записью остаётся свежей.

Объединяются только известные поля приоритетов/Min/Max осей с уникальным Address
и известные поля настройки инструмента/коллизий/СК. Неизвестные выражения и
xml_sha256-проверки скалярного XML читаются прежним способом. Отсутствующее поле
читается отдельным исходным выражением; затем полные снимки обновляются снова,
чтобы не передать старое состояние коллизий в recording-аудит. Изменение наличия
поля в ходе такой проверки, неполный ответ, неоднозначная ось/поле или повреждённый
XML останавливают очередь. Значения по умолчанию не подставляются.

Три компонента ToolAxisConstraint.ReferenceVector намеренно читаются отдельно:
при неактивном ограничении они отсутствуют в полном XML PowerMill 2023.
Worker по-прежнему проверяет свежие PID/версию/Busy/путь/полный список моделей
перед каждым фактическим XML-запросом и после пакета. Root HELP, независимая
сверка моделей, макросы/receipt/хеши и устойчивые контрольные точки сохранены.
В verification_passed поле settings_snapshot содержит счётчики запросов,
извлечённых полей, отдельных чтений и обновлений. Таймеры settings_snapshot.*
включаются обычным Profiler. Живое ускорение 0.4.1 пока не измерено.

В 0.4.0 CLI принимает `--timing-output NEW_FILE` для подготовки, аудита или run.
Файл должен быть новым и отдельным от входов/выходов; он пишется после операции,
включая обработанную ошибку. Для run добавляются таймеры работника. Пример:
`python -m powermill_com_helper prepare-simulation request.json NEW_DIR --timing-output timing.json`.
Полный снимок Profiler включает неуспешные интервалы и не должен суммироваться
по вложенным inclusive-временам. В state/events нативное время сохраняется
также при последующей ошибке проверки. При тайм-ауте native_seconds=null,
operation_seconds — длительность попытки помощника, а не известное время решателя.
failure_phase отличает native/native_result/postchecks. Время выполнения макроса
не разделяет внутренние IK, столкновения и I/O PowerMill.

Офлайн-проверка:

```text
python -m unittest discover -s powermill_com_helper/tests -t . -v
```

Тест PS5 использует подставное приложение и запрещает GetActiveObject.
Первое нативное испытание нового генератора — на небольшой копии в пределах
разрешённого задания. Успех тестов Python не подтверждает нативный синтаксис.

## Совместимость и новые чтения 0.5.0

Охраняемые операции принимают COM-версии 2023000, 2023003 и 2023101; версия
живого сеанса обязана точно совпадать с guard. Это совместимость профиля,
а не подтверждение всех расчётов и симуляций на каждой версии.

В белый список Python и PowerShell добавлены документированные чистые функции
number_selected, get_folders, active_folder и component_has_point_parameter.
Источник: установленный lib/locale/C/PARREF/stdlib.html. Последняя проверяет
наличие ключа в компоненте; значения и адреса PP по-прежнему читай отдельно.

identity_mode=geometry для сортировки проверяет уникальные XYZ голов и
необязательные оси, без чтения PP. Совпадающие XYZ запрещены даже при разных
LP/слоях. Фактические PP проверяй отдельным этапом; этот режим не является их
аудитом. По умолчанию остаётся identity_mode=layer_lp.

Сырой ответ каждой завершившейся нативной команды сохраняется в
native-result-SHA256_OPERATION_ID.json до проверки постусловий; имя файла
закрепляется в state.json, исходный ID и ответ — внутри JSON. Хеш вместо ID
исключает выход пути за каталог запуска. Тайм-аут без ответа
не создаёт вымышленного результата и требует согласования состояния.

`guard.model_identity_receipts` — необязательный список `{name,path}` для
порученного создания моделей. Путь абсолютный, receipt содержит 32-значный
шестнадцатеричный ID. Первоначальные ID моделей сохраняются в guard. Новый ID
принимается только при точном совпадении всего состава проекта и живого имени/ID;
после этого он закрепляется в model-identities.json с хешем плана и целостности.
Подмена или исчезновение receipt после закрепления блокирует продолжение, в том
числе после перезапуска помощника. Receipt не разрешает создание и не является
автоматическим обходом смены проекта.
